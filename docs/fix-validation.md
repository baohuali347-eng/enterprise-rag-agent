# 澄清与操作章节遗漏修复：2026-11-04

## 改动

路由新增 `clarify`，结合独立查询和最近对话识别缺少功能或操作对象的情况。该分支直接返回补充问题，不初始化检索器，也不执行生成和反思。用户补充后，澄清问题和补充信息进入正常历史，由现有查询改写与知识库流程继续处理。

澄清只针对必要对象缺失。功能明确、只问一般方法或操作入口时默认查询知识库；具体期望值、实例名称和可选条件不应成为回答一般方法前的必填项。明确问题的答案未知、属于租户私有配置或超出语料覆盖，仍由知识库链路判断，避免把这些问题都当成表达不清。

检索完整模式的重排候选池由 20 扩为 40，使用 `config.RERANK_CANDIDATE_K` 配置。最终输出仍最多 5 个去重父块。此次没有修改分块或索引，因此可以直接使用上一步索引。无重排的 `hybrid` 对照沿用原候选规模。

重排分数现在直接按输入的 chunk ID 对齐。原来根据文本反查 ID 的方式会把不同文档的相同文本都绑定到第一个 ID；新增测试覆盖重复文本和缺失 ID，验证来源不被错配。
