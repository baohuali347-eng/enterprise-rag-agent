## 题集来源与覆盖

题集位于 `kb_agent/eval/datasets/user_scenarios.json`，目前版本为 1.0，共 20 个场景、24 轮。

这是基于项目现有语料设计的用户口吻题集，由本次协作中的助手根据原文编写和核对；`manually_designed` 表示固定编写的场景，区别于旧脚本批量抽样生成的题。它不是采集到的真实用户日志，没有经过独立人工验收，也不是独立的最终测试集。后续若根据这些题调整系统，需要另外保留未参与调参的测试题。

| 分类 | 场景数 | 轮数 | 目的 |
|---|---:|---:|---|
| direct | 4 | 4 | 直接询问操作或能力 |
| colloquial | 4 | 4 | 口语表达、业务诉求和症状描述 |
| multi_turn | 4 | 8 | 指代、省略、条件改变、相近操作区分 |
| in_domain_unanswerable | 4 | 4 | 当前语料缺少具体步骤、租户配置或企业私有信息 |
| out_of_domain | 2 | 2 | 知识库边界与实时信息 |
| ambiguous | 2 | 2 | 缺少对象时应先澄清 |

每轮标注 `expected_behavior`、参考要点、标注说明。可回答题必须提供 `doc_id` 和可在原文中找到的引用片段；无答案标签限定于当前语料及可用工具，不能推导成产品不支持该功能。

题集保存完整语料的 SHA-256；校验时逐条验证引用片段，并检查语料快照是否一致。语料更新后必须复核可回答性和原文依据。字段及唯一 ID 由 Pydantic 校验。

补充检查题集 `kb_agent/eval/datasets/generalization_checks.json` 包含 8 个场景、10 轮，在澄清及候选池修复前固定，覆盖新的模糊表达、功能限制、先澄清后补充信息以及明确历史下的追问。它由同一协作助手根据语料编写，属于额外回归检查，不能视为独立人工保留测试集。冻结记录在 `data/eval/step4-checks-frozen.json`。

## 运行

```bash
# 不调用 API：校验题目格式、语料快照和原文依据
make scenarios-check

# 实际执行全部场景，需要 .env 中的 DEEPSEEK_API_KEY
make scenarios

# 只复现指定场景；同一多轮场景会完整执行
uv run python -m kb_agent.eval.run_scenarios --case-id multi-01

# 关闭反思作对照；不覆盖原报告
uv run python -m kb_agent.eval.run_scenarios --no-reflect

# 补充场景，独立保存运行结果
uv run python -m kb_agent.eval.run_scenarios --dataset kb_agent/eval/datasets/generalization_checks.json
```

默认每次创建独立的 `data/eval/scenario_runs/<时间>/`。显式指定 `--output-dir` 时该目录必须不存在，避免覆盖历史结果。旧评测的 `make eval`、`make ablate` 和分数文件保持独立。

每个场景从空历史开始。多轮问题把前面实际生成的回答存入历史，再执行后续问题，不向问答模型灌入预先写好的正确答案；多轮场景可以包含“澄清→补充后回答”等不同预期行为。某轮问答发生异常时，后续轮标为 `blocked`，下一个场景仍正常运行。裁判失败不会阻止后续轮获得已有真实历史。

## 指标口径

所有质量指标均为模型辅助判断，不等同于人工验收。裁判读取预期行为、参考要点、原文依据、本轮实际检索上下文和最终回答；历史或参考答案不能代替本轮检索上下文成为回答的依据。目前生成器和裁判都使用同一个配置模型，存在自评偏差。

单轮成功需要同时满足：

1. 行为与标注一致：回答、拒答或澄清。
2. 满足参考答案中的关键事实和用户当前意图。
3. 事实及引用得到本轮实际资料支持。
4. 引用编号均存在；可回答题至少有一个编号引用。编号存在由程序校验，语义支撑由裁判判断。

| 字段 | 定义 |
|---|---|
| `task_success_rate` | 所有预期轮次中成功的比例，覆盖回答、拒答和澄清 |
| `answer_success_rate` | 可回答轮次中正确完成回答的比例；原场景集分母为 16，补充检查集分母为 5 |
| `false_refusal_rate` | 已完成裁判判断的可回答轮次中，实际被判为拒答的比例；同时报告分子及判断覆盖数 |
| `correct_decline_rate` | 预期拒答轮次中成功拒答的比例；区分领域内缺失与领域外问题见分组结果 |
| `clarification_success_rate` | 预期澄清轮次中成功请求必要补充信息的比例 |
| `case_success_rate` | 场景内所有轮次均成功的场景比例，多轮场景不能只看最后一轮 |
| `latency_seconds` | 返回有效答案的请求耗时，包含路由、检索、生成、反思及重试，排除裁判和写结果文件的耗时；报告均值、p50、p95、最大值 |

原来“忠实度为 1 的拒答”不会自动算作回答成功；答非所问也不会因为引用编号存在而通过。

问答异常和后续 `blocked` 轮次计为任务未成功。裁判异常单独记录为 `judge_error`，受影响的成功率输出 `null`，不能把裁判失败当成系统答错。误拒答率仅在已判定的可回答轮次上计算，必须结合 `answerable_judged / answerable_turns` 阅读。问答异常耗时单独列出，不混入有效答案的延迟分布。

首个请求在新进程内执行，可能包含模型加载；另报告 `latency_excluding_first_request_seconds`。后者只是去掉首请求，没有运行独立预热流程。评测按场景顺序串行执行，不代表并发吞吐。小样本的 p95 也不能直接推广为生产延迟。

## 产物与复现

- `dataset.json`：运行时题集副本。
- `metadata.json`：模型、裁判、检索参数、设备、软件与系统版本、所选题目、语料/题集/索引/源代码指纹及计时口径，不保存 API key。
- `results.jsonl`：逐轮结果，及时落盘；包含实际历史、原问题、独立查询、最终答案、检索块全文及得分、反思、裁判、问答与裁判耗时。
- `report.json`：总体和分类统计。

`ask(..., with_trace=True)` 保存每次节点更新，包括反思重试前后的检索和生成结果。节点耗时由相邻更新到达的时间差估算，包含图调度开销；端到端耗时在调用 `ask()` 外计量，不能用节点耗时求和代替。

外部异常只记录类型，不将可能含请求头或凭据的异常原文写入产物。异常退出前已完成的逐轮结果仍可保留；只有完整结束才生成最终汇总。
